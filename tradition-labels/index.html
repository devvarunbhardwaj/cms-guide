The idea

The key is the address, the text is what shows

The website has a fixed set of spots, each with an address. It looks for the row whose key is exactly that address and prints its text there. If no row has that key, the spot stays blank. No error is shown.

First tab shows “Placement”

The key matches the spot exactly. The first part (tab/) says which part of the section the spot is in.

Key: never change it

It is fixed by the website code. Copy it exactly: lowercase, with the / and the dashes, no spaces.

Text: change it any time

Rewrite the words as you like. The website still knows where they go, because the key stays the same.

Order: doesn't matter

Rows can be in any order. If the same key is entered twice, the first row is used.

Good to know

Rules and notes

Only for Home · Tradition

These keys go only in the labels list of Home · Tradition. Other entries (Site · Labels, About pages and so on) have their own lists with different keys. Putting a Tradition key there does nothing.

Research tab: skip for now

The CMS also knows keys like landscape/…, labs/…, impact/…, patents/caption. The website doesn't read them yet; that tab's words are still in the site code. Adding them is harmless but changes nothing.

A typo fails silently

A wrong key (missing /, extra space, capital letter) isn't flagged. The spot just stays blank. If a label doesn't show after publishing, check the key letter by letter.

Empty text = blank spot

A row with the right key but no text also leaves the spot blank. Buttons with no text are hidden.
