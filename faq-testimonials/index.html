Part 1

The FAQ section

Every question on the site lives in one place: Content Manager → Home · FAQ. There is no separate FAQ on each programme. Each question decides for itself where it shows, with its pages box.

One question = one row in Home · FAQ → entries

FieldWhat to typeWhat it does on the site
group *The tab name, e.g. admissions, Fees, campus-lifeThe tab the question sits under. Tabs appear in the order they first appear in the list. A lowercase name like campus-life shows as “Campus Life”; anything with a capital letter shows exactly as typed.
question *The questionThe accordion row title.
answer *Plain textShown when the row is opened.
pagesAddresses, one per line. Empty = general.The scoping field. Empty → a general question (home page and every page with no questions of its own). Filled → the question shows only on those addresses. See Scope a FAQ.
scope *landing · admissions · bothOnly for general questions, and only on two pages: landing = home page only, admissions = /admissions/faqs only, both = both. Programme pages and school hubs ignore it.
cta_label / cta_linkOptionalSaved, but not shown on the site today. Leave empty.

Part 1 · How to

Scope a FAQ to one programme, or share it

Examples use real addresses. “ABC” = MBA /programs/business/mba, “XYZ” = MBA Strategic HR /programs/business/mba-strategic-hr.

First, get the page's address

Open the programme on the website and copy everything after the domain. For https://…/programs/business/mba type /programs/business/mba. A missing leading slash is added and a trailing slash is removed for you; anything else must match exactly.

A · A FAQ only programme ABC shows
  1. Content Manager → Home · FAQ → scroll to entries → Add an entry.
  2. group: the tab, e.g. Admissions. question / answer: the text. scope: leave both (it is ignored for limited questions).
  3. pages:
/programs/business/mba
  1. Repeat for each MBA-only question. Save → Publish → Publish to website.

Result: the MBA page shows only these questions, grouped by their tabs. The home page, every other programme and every school hub are unchanged.

B · Programmes ABC and XYZ share the same FAQ

Do not copy the question twice. Make it once and put both addresses in its pages box, one per line:

/programs/business/mba
/programs/business/mba-strategic-hr

Edit the answer once and both pages change together. A question can list as many addresses as needed. A comma also works as a separator.

Mixing shared and own questions, for example:

Questionpages boxABC (mba)XYZ (mba-strategic-hr)Home

* ABC and XYZ have their own questions, so the general set no longer shows there. Every other programme, with no own questions, still shows Q4.

C · ABC needs its own questions and a general one

A question is either general (empty box) or limited (filled box), never both. Putting ABC's address in the hostel question would take it off the home page. So:

  • Make a second copy of the general question with the pages box filled for ABC (and XYZ, if they share). The original stays empty, for the home page and everyone else.
Option, not built: the rule could be changed to “own questions plus the general set” so no copies are ever needed. That is a small site change; it also means every programme with its own questions grows longer. Decide before we change it.
D · One FAQ for a whole school, or for every programme

End an address with /* to cover everything under it.

Typed in pagesCoversDoes not cover
/programs/business/mbaThat one programme pageAnything else
/programs/businessThe Business school hub page onlyThe programmes under it
/programs/business/*Every Business programme pageThe Business hub itself (add /programs/business as a second line if wanted)
/programs/*Every programme page and every school hub/programs itself, home, admissions
A wildcard counts as “own questions”. Put /programs/business/* on one question and all Business programmes stop showing the general set. Use it on purpose.
E · Tabs: naming and order
  • The tab is whatever is typed in group. Tabs run in the order each name first appears in the entries list. Drag rows to reorder.
  • Type the same name the same way every time. admissions and Admissions are two different tabs that both read “Admissions”.
  • On a scoped page, only the tabs that hold one of its questions show. One tab = still drawn as a single tab.
  • Tabs in use today: general, admissions, academics, campus-life, International Students, Health and Safety. Reuse these where they fit.

Address tester

Paste a question's pages box on the right and a page address on the left to see if the question will show there. It uses the same matching the site uses. Nothing is saved.

The Student Testimonials section

The black “In their words · Student Testimonials” track of person cards. It looks the same everywhere, but it has two data sources: the university list (programmes, school hubs, /about/testimonials) and the landing page's own list (/lp pages).

Not the same thing:
  • Placed students on a programme page (cards with company logos, “Placements” anchor) = Data · Placed Student, picked on each programme. Per programme; hidden where none are picked.
  • Home · Testimonials = the dignitary video reels, the achiever video strip, Instagram reels and the Message-tab quotes. Different section, different entry.

How to fill the university list

  1. Content Manager → Home · Placement → achievers: name, designation, placed_in (company), salary_value (12), salary_unit (LPA), company_logo, person_image (a cut-out portrait, transparent background).
  2. Home · Placement → success_stories: stream, name, designation, company_image (fill its alternative text with the company name in the Media Library), person_image.
  3. Data · School Hub → success_story_quotes: one sentence per row.
  4. Headings: Page · Program Defaults → testimonials_heading for programme pages, Data · School Hub for hubs, Page · About for /about/testimonials. Wrap the red italic words in *asterisks*.
  5. Save → Publish → Publish to website. One edit updates every programme, hub and /about/testimonials together.

How to fill a landing page's own list

  1. Content Manager → Landing Page → the page → sections → add testimonials (or open the existing one).
  2. students, one row each: name *, company *, at (replaces the company on the card), quote (their own words; empty = no quote), photo *, logo *.
  3. Leave title, anchor empty to take them from Page · LP Defaults → Testimonials. Anything typed on the page wins.
  4. hide on = section left off the page; its rows stay saved.

Can programme ABC have its own testimonials?

Not today. Every programme shows the same university list. What is per programme now is Placed students (Data · Placed Student, picked on the programme), a separate section.

Options, not built, need a go:
  • Pick on the programme: a “testimonials” picker on Data · Program, like placed students. Empty = the university list, as now. Clear for editors; one place per programme.
  • A pages box on each story, like the FAQ: /programs/business/* on a Business graduate. Shares across many programmes in one row.
  • Either way, add a quote field on each person so the words belong to the person who said them, and retire the cycled placeholders.
What if they don't fill it

Fallbacks, failures and hidden sections

Three outcomes: the site falls back to something else, the section hides, or Publish to website stops and the live site stays exactly as it was until the field is fixed.

Save→Publish→Publish to website→Live

A saved draft never reaches the site. A row missing a required field stops “Publish to website” with “a required field is incomplete — dropped row N”; nothing is changed on the live site.

Do

  • Copy page addresses from the browser.
  • One shared question with several addresses, not copies.
  • Fill the company image's alternative text.
  • Use cut-out portraits on a transparent background.
  • Click Publish to website after publishing in the CMS.

Don't

  • Add a wildcard (/programs/*) without meaning it: it removes the general set from every page it covers.
  • Spell a tab two ways (fees / Fees).
  • Fill cta fields expecting a button.
  • Leave the placeholder quotes on real people at launch.
